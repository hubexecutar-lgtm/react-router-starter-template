São os artefatos do pack gerado, mas tecnicamente o conjunto atual ainda não é um PWA instalável completo.

O que você tem hoje:

  • risco-cognitivo-a4-pack-unificado.html — aplicação web local principal com Status Report + Plano Semanal e exportação A4. 
  • status-report-a4-rc.html — artefato individual de Status Report. 
  • plano-semana-a4-rc.html — artefato individual do plano semanal. 
  • risco-cognitivo-tokens.css — design tokens compartilhados. 
  • manifest.yaml — manifesto de governança do pack, não o Web App Manifest de PWA. Ele registra ID, versão, outputs, tokens e regras de impressão. 
  • verification.json — gate de verificação estática, incluindo A4, duas folhas, ausência de dependências externas e tokens. 
  • README.txt — documentação do pacote e decisões de unificação. 

README.txt

Para virar um PWA real e compartilhável com seus seguidores, faltam principalmente:

index.html
→ tela inicial + “como usar em 3 passos”

form.html ou formulário embutido
→ usuário preenche os próprios dados

prisma.html
→ renderização dinâmica usando o template A4

manifest.webmanifest
→ nome, ícones, start_url, display: standalone, cores

service-worker.js
→ cache e funcionamento offline

icons/
→ 192×192, 512×512 e maskable

app.js
→ formulário → estado local → preenchimento do template → preview

print.css
→ @page A4 + exportação do PDF

O fluxo final ficaria:

Abrir PWA
→ 1. Entenda em 3 passos
→ 2. Preencha o formulário
→ 3. Veja seu Prisma
→ Exportar PDF
→ Salvar / compartilhar

A vantagem é que podemos reaproveitar diretamente o sistema visual e os componentes A4 atuais. O pack já foi construído sem dependências externas e com impressão A4, o que facilita bastante transformá-lo em uma PWA offline-first.
